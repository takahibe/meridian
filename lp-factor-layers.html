🎯 Fee Capture (API-driven)

Yield is read directly from Meteora's feePerTvl24h API field — not locally computed. DLMM fee accrual depends on active bin placement, swap routing, and dynamic fee state that only the pool contract tracks accurately.

yield_24h = meteora_api.feePerTvl24h ← NOT (fee_tvl * size * range_eff)

Evidence: Meridian reads this value directly. 97.2% of 71 deploys earned fees. Avg $0.46/deploy. Range efficiency has weak PnL correlation (r=0.124).

⚖️ Time-in-Range > Breakeven Days

Breakeven = position_size / (daily_fees − daily_il) is conceptually sound but IL is path-dependent and hard to compute in real-time. The actual data shows time-in-range is the dominant profitability driver.

profitability ∝ minutes_in_range × fee_per_tvl_24h

Evidence: Avg position lives 50 min (median 33). Trailing TP (long in-range) = 100% win rate, +2.60% avg. OOR exits (short in-range) = 52.5% win, +0.12% avg. Duration↔PnL r=+0.136.

📐 Bin Width (sqrt scaling + fragility)

Sub-linear (sqrt) scaling is empirically superior to linear. Volatility has diminishing returns on optimal range width. Fragility adjustments are the strongest Darwin signal (weight: 1.63).

bins = clamp(35 + sqrt(vol/5) × 0.7 × 34, 35, 69) × fragility_mult

Fragility: ultrafragile → 0.35×, fast → 0.6×, normal → 1.0×. At vol=2: sqrt→53 bins vs linear→49. At vol=5: sqrt→59 vs linear→69 (saturated). Evidence: vol↔PnL r=+0.177 (weak). sqrt prevents over-width at high vol.
